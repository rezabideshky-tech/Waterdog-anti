# ArvanShield — امنیت ورود WaterdogPE با Java 21

ArvanShield افزونه‌ای برای WaterdogPE است که ضدربات و محافظ ورود را با پایش تجمیعی ترافیک شبکه ترکیب می‌کند. پیام‌های بازیکن و مدیر به انگلیسی رنگی نمایش داده می‌شوند.

### نسخهٔ پراکسی موردنیاز

هر دو افزونهٔ `ArvanShield` و `WaterdogLobbyFallback` با API رسمی `dev.waterdog.waterdogpe:waterdog:2.0.4-SNAPSHOT` کامپایل می‌شوند. برای اجرا از build جدید رسمی WaterdogPE که همین API را دارد استفاده کن؛ `v2.0.3` قدیمی‌تر با API متریک موردنیاز ArvanShield سازگار نیست. [نسخه‌های رسمی WaterdogPE](https://github.com/WaterdogPE/WaterdogPE/releases)

## قابلیت‌ها

- محدودسازی ورود بر پایهٔ IP، زیرشبکه، XUID و فشار کلی ورود با token bucket بدون قفل سراسری.
- حالت‌های `off`، `observe`، `balanced` و `attack`؛ حالت پیش‌فرض `observe` است و بازیکن را رد نمی‌کند.
- پاک‌سازی دوره‌ای داده‌ها و سقف سخت برای شمارنده‌های حافظه؛ در پرشدن سقف، شمارندهٔ کل همچنان کار می‌کند.
- اتصال به رابط رسمی `NetworkMetrics` در WaterdogPE برای شمارش تجمیعی بایت‌ها، بسته‌های عبوری، دیتاگرام‌های حذف‌شده و صف‌های انتقال بیش‌ازحد.
- گزینهٔ اختیاری برای جلوگیری از ورودهای جدید هنگام فشار پایدار شبکه؛ فقط در حالت `attack` و فقط وقتی مدیر آن را در تنظیمات روشن کرده باشد. بازیکنان متصل قطع نمی‌شوند.
- اگر افزونهٔ دیگری قبلاً `NetworkMetrics` تنظیم کرده باشد، شمارنده‌های آن حفظ و فراخوانی‌هایش ادامه داده می‌شوند.
- هیچ IP یا XUID خامی در لاگ یا حافظهٔ شمارنده‌ها ذخیره نمی‌شود؛ XUIDهای قابل‌اعتمادِ اختیاری در فایل تنظیمات هستند.

## مرز مهم محافظت بسته‌ها و DDoS

نسخهٔ عمومی Plugin API در WaterdogPE شمارنده‌های کلی شبکه را می‌دهد، اما رویداد امن و قابل‌لغو برای **تک‌تک بسته‌های خامِ هر بازیکن** ارائه نمی‌کند. بنابراین ArvanShield بستهٔ خام را از Netty حذف یا دست‌کاری نمی‌کند؛ این کار با بازتاب Java یا تزریق handler داخلی شکننده است و می‌تواند پروکسی را خراب کند. افزونه ترافیک را پایش می‌کند و در حالت حمله می‌تواند ورودهای جدید را موقتاً نگه دارد؛ برای فیلتر دقیق هر بسته باید WaterdogPE خودش یک hook رسمی قابل‌لغو ارائه کند.

حملهٔ حجمی UDP که پهنای‌باند VPS را پیش از رسیدن به Waterdog پر کند نیز در اختیار افزونه نیست. برای آن، محافظ DDoS شرکت میزبان که ترافیک UDP/RakNet بازی را پشتیبانی کند لازم است. ArvanShield جایگزین فایروال یا محافظ شبکه نیست.

## نصب

1. با Java 21 و Maven بساز:
   ```bash
   mvn -f arvanshield/pom.xml clean verify
   ```
2. کپی کن به پوشهٔ `plugins/` مربوط به WaterdogPE:
   `arvanshield/target/arvanshield-1.1.0.jar`
3. پروکسی را راه‌اندازی مجدد کن. فایل `plugins/arvanshield/config.yml` ساخته می‌شود.
4. ابتدا `mode: observe` را نگه دار و آمار را در زمان عادی و اوج ترافیک بررسی کن.

## حالت‌ها

- `off`: تصمیم‌های ضدربات و واکنش فشار شبکه خاموش.
- `observe`: آمار و تصمیم احتمالی را گزارش می‌کند؛ ورود را مسدود نمی‌کند.
- `balanced`: محدودیت محافظه‌کارانهٔ ورود را فعال می‌کند؛ حداقل دو دستهٔ مستقل سیگنال لازم است. IP و زیرشبکه یک دسته محسوب می‌شوند.
- `attack`: آستانهٔ پایین‌تری برای امتیاز ورود دارد. اگر مدیر گزینهٔ `shed-new-logins-on-high-load-in-attack-mode` را هم روشن کند، فشار شبکه باید به مقدار تعیین‌شده برسد و در چند نمونهٔ پیاپی ادامه داشته باشد تا فقط ورودهای جدید موقتاً رد شوند.

### تنظیم محافظ ترافیک

در `config.yml`:

```yaml
packet-guard:
  enabled: true
  shed-new-logins-on-high-load-in-attack-mode: false
  attack-inbound-decoded-bytes-per-second: 0
  attack-sustained-windows: 5
  attack-cooldown-seconds: 15
```

مقدار `0` یعنی واکنش خودکار به فشار کلی غیرفعال است. این مقدار را تا وقتی آمار طبیعی سرور را ندیده‌ای تغییر نده. سنجهٔ ورودی، **بایت بازشدهٔ بسته‌های کلاینت در کل پروکسی** است، نه سرعت دقیق لینک اینترنت و نه شمارندهٔ هر بازیکن. حد مناسب به Waterdog، بازی‌ها و تعداد بازیکنان خودت بستگی دارد. گزینهٔ `shed-new-logins...` پیش‌فرض خاموش است تا تنظیم اولیه باعث اختلال نشود.

## فرمان‌های مدیر

```text
/arvanshield status
/arvanshield mode <off|observe|balanced|attack>
/arvanshield reload
```

فرمان نیازمند مجوز `arvanshield.admin` است. تغییر حالت با فرمان تا راه‌اندازی مجدد موقت است؛ برای ماندگاری، `mode` را در `config.yml` تغییر بده. پیام‌های بازی و فرمان‌ها انگلیسی و رنگی هستند.

## سازگاری Bedrock

ArvanShield نسخهٔ کلاینت را سیگنال ربات نمی‌داند و بازیکن نسخهٔ `1.20` یا `1.26.30` را صرفاً به‌خاطر شمارهٔ نسخه رد نمی‌کند. افزونه نسخهٔ پروتکل اضافه نمی‌کند؛ پشتیبانی نهایی وابسته به همان build از WaterdogPE و backend است. هر نسخه را روی شبکهٔ آزمایشی خودت بررسی کن.

## ایمنی و آزمون

- ابتدا `observe` را در ساعات معمول و اوج اجرا کن؛ بعد از بررسی آمار، `balanced` را آزمایش کن.
- `attack` و بستن ورودهای جدید را فقط هنگام حملهٔ واقعی و پس از تنظیم آستانه‌های متناسب با سرور فعال کن.
- هیچ سقف عمومی‌ای برای همهٔ شبکه‌ها امن نیست؛ NAT اپراتور موبایل، تعداد بازیکنان واقعی و دانلود بستهٔ منابع روی ترافیک اثر دارند.
- آزمون فشار را فقط روی سرور آزمایشی خودت انجام بده.
- ساخت و آزمون‌ها:
  ```bash
  mvn -f arvanshield/pom.xml clean verify
  ```
