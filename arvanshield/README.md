# ArvanShield — آنتی‌بات WaterdogPE

ArvanShield یک افزونهٔ مستقل برای **پراکسی WaterdogPE با Java 21** است. بررسی اصلی در رویداد قابل‌لغو `PlayerAuthenticatedEvent` انجام می‌شود؛ یعنی پس از decode شدن اطلاعات ورود و پیش از انتخاب/اتصال به backend. برای تصمیم‌گیری از نسخهٔ کلاینت، مدل دستگاه یا `deviceId` استفاده نمی‌شود.

## سازگاری Bedrock

این افزونه روی دادهٔ ورود استاندارد WaterdogPE کار می‌کند و بازیکن نسخهٔ `1.20` یا `1.26.30` را صرفاً به‌خاطر نسخه‌اش رد نمی‌کند. **ArvanShield پشتیبانی پروتکل اضافه نمی‌کند**؛ خود WaterdogPE و زنجیرهٔ backend شما باید از هر دو نسخه پشتیبانی کنند. نسخه‌های واقعی را روی همان build پراکسی و backend خودتان آزمایش کنید.

## نصب

1. فایل `arvanshield-1.0.0.jar` را از artifact با همین نام در GitHub Actions دانلود کنید؛ یا از ریشهٔ مخزن اجرا کنید:
   ```bash
   mvn -f arvanshield/pom.xml clean package
   ```
2. کپی کنید به پوشهٔ `plugins/` مربوط به WaterdogPE و پراکسی را راه‌اندازی مجدد کنید.
3. فایل `plugins/arvanshield/config.yml` را بررسی کنید. حالت پیش‌فرض `observe` است و اتصال کسی را رد نمی‌کند.
4. پس از بررسی لاگ‌ها در ساعات عادی و اوج ترافیک، برای اعمال محافظت، `mode: balanced` بگذارید و پراکسی را restart کنید؛ یا موقتاً دستور `/arvanshield mode balanced` را اجرا کنید.

## حالت‌ها

- `off`: محاسبهٔ ریسک و محدودسازی خاموش.
- `observe`: سیگنال‌ها و مواردی را که در `balanced` رد می‌شدند می‌شمارد/نمونه‌برداری می‌کند؛ **هیچ بازیکنی را رد نمی‌کند**.
- `balanced`: فقط وقتی امتیاز از آستانه بگذرد و حداقل دو دستهٔ مستقل سیگنال وجود داشته باشد، همان تلاش ورود را رد می‌کند.
- `attack`: آستانهٔ پایین‌تری دارد، اما همچنان شرط سیگنال‌های مستقل را رعایت می‌کند. این حالت را فقط هنگام موجی که واقعاً حمله تشخیص داده‌اید فعال کنید.

IP و subnet یک دستهٔ مشترک به نام `NETWORK` هستند؛ بنابراین IP مشترک، NAT اپراتور موبایل یا خانواده به‌تنهایی باعث رد اتصال نمی‌شود. سیگنال‌های اصلی عبارت‌اند از نرخ اتصال IP/subnet، تکرار XUID، و فشار کلی ورود. مقادیر `limits` و `risk` در config قابل تنظیم‌اند.

فرمان مدیریتی (نیازمند permission برابر `arvanshield.admin`):

```text
/arvanshield status
/arvanshield mode <off|observe|balanced|attack>
/arvanshield reload
```

تغییر mode با دستور تا restart بعدی موقت است؛ برای ماندگاری، config را ویرایش کنید. `reload` تنظیمات را از دیسک می‌خواند و mode را به مقدار config برمی‌گرداند.

## رفتار و محدودیت‌های مهم

- در نسخهٔ 1.0، محافظت بر پایهٔ امتیاز ریسک، token-bucket و رد زودهنگام است؛ **captcha یا چالش تعاملی ندارد** و بازیکن مشکوک را به backend verify هدایت نمی‌کند. تشخیص قطعی باتی که با حساب معتبر و از IPهای پراکنده، دقیقاً مثل بازیکن رفتار کند بدون challenge یا سیگنال backend ممکن نیست.
- هیچ IP/XUID به‌صورت دائمی ban نمی‌شود. باکت‌ها در حافظه‌اند، زمان‌دارند و تعدادشان محدود است؛ اگر حد حافظه پر شود، شمارش per-key برای کلیدهای جدید fail-open می‌شود و باکت کلی همچنان کار می‌کند.
- XUIDهای تأییدشدهٔ قبلی یا داخل `trusted-xuids` فقط تخفیف امتیاز می‌گیرند و bypass کامل نیستند.
- `security.require-xbox-authentication` به‌صورت پیش‌فرض خاموش است. فقط وقتی روشنش کنید که **همهٔ بازیکنان مجاز** باید Xbox Live-authenticated باشند؛ روی شبکه‌هایی با حالت offline یا تنظیمات خاص Floodgate می‌تواند بازیکن واقعی را رد کند.
- شناسه‌های rate-limit در حافظه با SHA-256 و salt تصادفیِ همان اجرای پراکسی نگه‌داری می‌شوند؛ IP، XUID یا `deviceId` در فایل یا لاگ ذخیره نمی‌شود. فهرست اختیاری `trusted-xuids` طبیعتاً XUIDهای واردشده را در config نگه می‌دارد.
- افزونه ترافیک حجیم UDP را پیش از رسیدن به WaterdogPE متوقف نمی‌کند. برای حملهٔ حجمی، فایروال/میزبانی با محافظت DDoS در لایهٔ شبکه لازم است.
- برای جلوگیری از اختلال، اول در `observe` رفتار واقعی شبکه را ببینید. افزایش آستانه‌ها یا کاهش ظرفیت‌ها را روی تعداد کاربران هم‌زمان و NATهای شبکهٔ خودتان تنظیم کنید؛ هیچ thresholdای برای همهٔ شبکه‌ها بی‌خطر نیست.

## ساخت

```bash
mvn -f arvanshield/pom.xml clean package
```

خروجی: `arvanshield/target/arvanshield-1.0.0.jar` (وابستگی WaterdogPE داخل JAR کپی نمی‌شود و باید توسط پراکسی فراهم شود).
