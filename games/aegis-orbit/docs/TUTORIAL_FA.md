# آموزش ساخت بازی Godot با کمک AI طبق استاندارد Agentic Game Factory

این سند نشان می‌دهد که پروژه‌ی **Aegis Orbit** چطور ساخته شده، چطور آن را اجرا و تست کنی، و چطور همین روش را برای بازی‌ی خودت به کار ببری. نکته‌ی مهم: **AI کد و دارایی پیش‌نویس می‌سازد، اما تأیید مفهوم، تست روی دستگاه واقعی، حساب فروشگاه و انتشار با انسان است.**

## ۱. بخش‌هایی که خودکار هستند و بخش‌هایی که انسانی‌اند

| کار | AI می‌تواند؟ | انسان باید؟ |
|---|---|---|
| طراحی مفهوم و قوانین بازی | پیش‌نویس | **تأیید** |
| نوشتن کد منطق و UI | بله | بازبینی |
| تست واحد (GUT) و تست بارگذاری اسکریپت‌ها | بله | اجرا و بررسی خروجی |
| بات خودکار (Autoplay) از طریق UI واقعی | بله | بررسی |
| تصویر و آیکن | بله (تصویر) | بازبینی و کپی‌رایت |
| **متن فارسی داخل تصویر** | **نه** — مدل‌های تصویری متن فارسی را خراب می‌کنند | با PIL و فونت Vazirmatn روی تصویر نوشته شود |
| صدا | بله (سنتز) | گوش دادن روی دستگاه |
| ساخت APK و امضا | دستورها را می‌نویسد | اجرا روی ماشین خودت؛ کلید امضا هرگز داخل پروژه نباشد |
| حساب فروشگاه، کارمزد، انتشار | نه | **انسان** |

## ۲. پیش‌نیازها

- **Godot 4.7.x** (نسخه‌ی استاندارد فکتوری ۴.۷.۱ است).
- **GUT 9.6.1** داخل `addons/gut` (در این پروژه از قبل هست).
- برای ساخت اندروید: **JDK 17**، **Android SDK** (build-tools 34، platform android-34) و قالب‌های خروجی Godot.
- برای تصویر و صدا: **Python 3** با `pillow` و `numpy`.
- نکته‌ی موبایل: ساخت و تست کامل روی گوشی عملی نیست. روی گوشی می‌توانی این آموزش را بخوانی و کد را در مرورگر ببینی، اما اجرای Godot و ساخت APK به کامپیوتر یا یک ماشین CI نیاز دارد.

## ۳. ساختار پروژه

```
games/aegis-orbit/
  project.godot          تنظیمات (gl_compatibility، stretch canvas_items + expand، autoloadها)
  scenes/main.tscn       صحنه‌ی اصلی؛ فقط یک Control که AppShell را می‌سازد
  scripts/               منطق و UI (orbit_logic.gd منطق خالص بازی است)
  tests/                 تست‌های GUT و test_scripts_load.gd
  tools/                 بات خودکار، تولیدکننده‌ی کش کلاس، ساخت تصویر و صدا
  assets/                تصویر، فونت، صدا
  export_presets.cfg     اندروید و لینوکس؛ addons/gut، tests و tools از خروجی حذف می‌شوند
  docs/CONCEPT.md        مفهوم بازی برای تأیید
  store/                 متن فروشگاه و بررسی طول متن‌ها
```

## ۴. گام به گام: اجرای پروژه

**گام ۱ — کش کلاس‌ها را بساز.** کد فقط با `class_name` کار نمی‌کند مگر کش کلاس‌های Godot ساخته شده باشد. ویرایشگر این کار را موقع باز کردن پروژه انجام می‌دهد؛ اجرای بدون ویرایشگر (تست یا CI) را با این فرمان آماده کن:

```bash
python3 tools/gen_class_cache.py
```

در این پروژه برای اینکه وابستگی‌ها ساده بمانند، کلاس‌های خودِ بازی با `preload` به هم وصل شده‌اند؛ فقط GUT به کش نیاز دارد.

**گام ۲ — بازی را در ویرایشگر اجرا کن.** پوشه‌ی `games/aegis-orbit` را در Godot باز کن و Play بزن. اولین بار آموزش سه‌مرحله‌ای نشان داده می‌شود.

**گام ۳ — تست‌ها.** یک فرمان کامل:

```bash
GODOT=/path/to/godot-4.7 tools/run_checks.sh
```

این فرمان سه کار می‌کند: کش، تست‌های GUT (شامل بارگذاری همه‌ی اسکریپت‌ها) و بات خودکار. خروجی GUT باید `All tests passed` باشد.

**گام ۴ — بات خودکار.** بات از طریق همان تابع ورودی انگشت (`feed_input`) نشانه‌گیری می‌کند و دکمه‌های واقعی (Play، Skip، Nova، Play again، جدول رکوردها، تنظیمات، زبان فارسی) را فشار می‌دهد. از پروفایل واقعی‌ات استفاده نمی‌کند: فایل ذخیره‌ی جدا دارد.

## ۵. گام به گام: خروجی اندروید

```bash
godot --headless --path games/aegis-orbit --export-debug "Android" releases/aegis-orbit/debug.apk
```

- قبل از این، در Godot مسیر Android SDK و JDK را در تنظیمات ویرایشگر وارد کن.
- نام پکیج در `export_presets.cfg` فعلاً `com.example.aegisorbit` است. قبل از انتشار عوضش کن.
- **کلید امضا را داخل پروژه نگذار.** برای انتشار، کلید را خارج از پروژه بساز و در هنگام خروجی از متغیرهای محیطی یا تنظیمات محلی استفاده کن.
- خروجی خودکار به یک Action در GitHub (مثل godot-multi-builder) هم ممکن است، اما آن Action آخرین بار در ۲۰۲۰ به‌روز شده؛ قبل از استفاده نسخه‌ی Godot و Docker image را بررسی کن.

## ۶. اصولی که این بازی به آن‌ها پایبند است

1. **منطق بدون گره (pure logic).** `orbit_logic.gd` بدون Node و بدون ساعت کار می‌کند؛ فقط `step(dt)` و یک seed. به همین خاطر تست و بات ممکن است، و آسمان روزانه برای همه‌ی بازیکنان در یک روز یکسان است.
2. **چیدمان از viewport زنده.** هیچ موقعیتی با عدد ثابت نیست. صفحه‌ها با `ScreenBase` وقتی اندازه‌ی واقعی را دارند ساخته می‌شوند و با تغییر اندازه دوباره ساخته می‌شوند. صفحه‌ی بازی هنگام چرخش ساخته نمی‌شود تا وضعیت بازی از دست نرود.
3. **دکمه‌ها باید در جعبه‌شان جا شوند.** متن فارسی بلند کوچک می‌شود (`fit_font_size`)، و تست `test_long_persian_button_labels_shrink_to_fit` این را کنترل می‌کند.
4. **گلیف‌ها.** تست `test_persian_text_is_fully_covered_by_the_font` بررسی می‌کند که فونت همه‌ی حروف فارسی متن‌ها را دارد. ایموجی داخل دکمه‌ها استفاده نشده است.
5. **تواین‌های حلقه‌ای به گره خودشان وصل‌اند.** `node.create_tween()` و نه `screen.create_tween()`. و تواین‌ها را فقط وقتی بساز که گره داخل درخت صحنه است؛ در غیر این صورت Godot خطای `Parameter "t" is null` می‌دهد. این خطا در ساخت این بازی پیدا و رفع شد.
6. **صدا.** فایل‌های WAV حلقه‌ای با `loop_mode` و `loop_end` (بر حسب نمونه) تنظیم می‌شوند. فایل‌ها بدون مرحله‌ی import خوانده می‌شوند تا فشرده‌سازی روی حلقه اثر نگذارد.
7. **ذخیره‌ی امن.** ذخیره با فایل موقت و نسخه‌ی پشتیبان (`.bak`) نوشته می‌شود. اگر فایل خراب باشد، از نسخه‌ی پشتیبان بازیابی می‌شود و پیشرفت پاک نمی‌شود.
8. **تلاش روزانه.** با شروع بازی روزانه، تلاش امروز مصرف می‌شود؛ بستن بازی وسط راه نمی‌تواند تلاش دوباره بسازد.

## ۷. مراحل ساخت بازی‌ی خودت با همین روش

1. **مفهوم.** یک صفحه بنویس: یک جمله‌ی بازی، حلقه‌ی اصلی، مکانیک امضا، حالت‌ها، کسب‌وکار (بدون گاچا و بدون pay-to-win)، پلتفرم، بازار. `docs/CONCEPT.md` را الگو بگیر و **تأیید کن** قبل از ساخت کد.
2. **معماری.** منطق خالص را جدا کن، تست بنویس، بعد UI.
3. **دارایی.** تصویر و صدا را با AI بساز، اما متن فارسی را با PIL و فونت روی آن‌ها بنویس. کپی‌رایت هر دارایی را در `LICENSES.md` ثبت کن.
4. **فروشگاه.** توضیح کوتاه فارسی حداکثر ۶۰ حرف، انگلیسی حداکثر ۸۰ حرف. آیکن فروشگاه باید مربع ساده باشد. `store/check_lengths.py` را اجرا کن.
5. **بررسی نهایی.** `tools/run_checks.sh`، بعد اجرای دستی روی دستگاه واقعی، بعد خروجی اندروید.

## ۸. چک‌لیست: چه چیزی در این پروژه تأیید شده و چه چیزی نه

**تأییدشده در محیط ساخت (با موتور Godot 4.7.2 در وب‌اسمبلی):**
- همه‌ی اسکریپت‌ها بدون خطای تجزیه بارگذاری می‌شوند؛ صحنه‌ی اصلی ساخته می‌شود.
- ۳۷ تست GUT گذشت (منطق، ذخیره، دستاوردها، رکوردها، متن‌ها، گلیف‌های فارسی، اندازه‌ی دکمه‌ها، بات).
- بات یک بازی کامل را از طریق UI واقعی تا پایان بازی انجام داد؛ ترتیب صفحه‌ها (آموزش، رکوردها، تنظیمات، فارسی، منو) بدون خطای زمان اجرا.
- مفهوم، آیکن (۱۰۲۴ و ۵۱۲ پیکسل، مربع ساده) و یک سنگ بازی بازبینی شد.

**تأییدنشده (نیاز به ماشین شما):**
- چیدمان روی گوشی واقعی و در جهت‌های مختلف؛ محل آموزش و اندازه‌ی متن‌ها.
- ساخت APK و نصب آن. اجرای امضا و خروجی لینوکس.
- عکس‌های صفحه‌ی فروشگاه (محیط ساخت رندر نمی‌کند).
- حس بازی، تعادل سختی برای انسان (بات فقط مرجع است) و صدا.
